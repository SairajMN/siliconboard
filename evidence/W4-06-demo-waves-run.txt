# W4-06 demo waveform run: counter with --waves --cross-sim on the de-ambiguated spec

## the spec ambiguity that broke the first attempt

The original line read "It does not need to wrap or flag overflow."
That is genuinely ambiguous, so the testbench agent wrote an overflow check that
raced the DUT by one cycle, and the run failed all 4 sims. The pipeline
behaved correctly: it refused to ship rather than passing a bad check.
Fixed in examples/counter/spec.txt to state saturation explicitly.

$ cat examples/counter/spec.txt
I need a small 8-bit up counter for a clock divider block. It should have a
clock and an active-low reset, both synchronous, plus an enable input so the
counter only advances when enable is high. Output is the current 8-bit count.
When the count would go past 255 it must saturate at 255 and stay there, and
there is no overflow flag. Target clock is 200 MHz.
