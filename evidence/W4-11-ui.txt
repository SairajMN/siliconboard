Two bugs found and fixed during verification:
  - ssh lacked -N: the remote shell got EOF and tore down the forward
    before the browser (or curl) could use it.
  - -L pointed at $PORT on the box instead of the ui port 8080, so a
    custom local PORT forwarded to a closed remote port ("connect
    failed: Connection refused" in the ssh log).
Both fixed in ui/tunnel.sh and re-tested: 200/200/200 through :8094.
